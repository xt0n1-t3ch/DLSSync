# Anti-cheat detection and the ban-risk warning

Swapping a DLL into a game folder, or forcing a DLSS preset through the NVIDIA driver profile, changes
what an anti-cheat sees at launch. Systems that hash game files or watch loaded modules — Easy
Anti-Cheat, BattlEye, Riot Vanguard, and others — can read that as a tampered file and kick or ban the
account. There are confirmed reports of bans in online titles after a DLSS DLL swap and even after a
driver-profile override applied through NVIDIA Profile Inspector. DLSSync therefore detects anti-cheat
per game and warns before any apply; it never blocks the action.

## How detection works

Detection is a hybrid of two sources, combined per game:

1. **Local binary fingerprint scan.** `crates/anticheat-detect` walks the game's install directory
   (shallow, depth-limited) and matches known anti-cheat binaries by filename — for example
   `EasyAntiCheat_x64.dll`, `BEService.exe` / `BEClient_x64.dll`, `vgk.sys` / `vgc.exe` (Vanguard),
   `GameMon.des` (nProtect GameGuard), `xhunter1.sys` (XIGNCODE3), `EAAntiCheat.GameService.exe`,
   `PnkBstrA.exe`, and `mhyprot*.sys`. A match on disk is strong evidence the anti-cheat ships with the
   game.

2. **PE binary inspection.** `crates/anticheat-detect/src/pe_inspect.rs` parses the largest game
   executable with `pelite` and `memchr`, looking for protector fingerprints that no dataset can
   replace: Denuvo's signature section cluster (`.arch`, `.shared`, `.data1`, `.data2`, `.sxdata`,
   `.xtext`, `.xtls`, `.nidata`, `.didata`, `.trace`, `.srdata`, `.text1`) and its `Denuvo` /
   `denuvo_atd` string markers; VMProtect (`.vmp0`/`.vmp1`/`.vmp2`); Themida / WinLicense
   (`.themida`/`.winlice`); Enigma Protector; Steam CEG (`.bind`). An entropy heuristic catches
   exploded, mostly-packed section tables even when no name or marker matched.
3. **Community dataset, in two merged layers.** A slim index distilled from
   [PCGamingWiki](https://www.pcgamingwiki.com/) at manifest-build time —
   `Middleware.Anticheat` for the anti-cheat engines, `Availability.Uses_DRM` for Denuvo / Arxan
   anti-tamper. The build-time pipeline ALSO overlays an AreWeAntiCheatYet pass for the Linux / Wine
   `status` field; that overlay lives only inside `manifest-builder` and never reaches the running app
   as a runtime dependency. Keyed by Steam app id and by a normalized game name (lowercase, ASCII
   alphanumerics only) so punctuation and casing never matter. At runtime the index resolves in two
   layers, freshest last:
   - the embedded snapshot in `crates/dll-catalog/anticheat-snapshot.json`, regenerated by
     `manifest-builder --emit-anticheat-snapshot`;
   - the CDN manifest `anticheat` index, merged over the snapshot when present.

The PE scan, the on-disk binary fingerprint scan, and the dataset are all merged into one report.
Local evidence (`binary` for filename hits, `pe` for protector fingerprints) wins the dedupe over
the `dataset` source on name collision, and dataset-only matches still surface. The lookup prefers
the Steam app id, then falls back to the normalized name. Each detection carries a risk `kind`:
`anti_cheat` (account-ban risk), `anti_tamper` (launch-fail risk on signature mismatch), or
`drm` (informational).

## The warning

When detection returns at least one anti-cheat, the game detail drawer shows a warning banner above
both apply paths — the DLL-swap "Apply selected" action and the per-game DLSS override panel. The banner
names the detected anti-cheats, includes the dataset's Linux/Wine status when known, and offers a
"Learn more" link that targets the matching per-game PCGamingWiki page when a Steam app id is known
(`https://www.pcgamingwiki.com/api/appid.php?appid={id}`) or the PCGW glossary entry for the strongest
detected kind otherwise. The apply still runs if you choose to proceed; the warning exists so the choice
is informed.

A clean game (no binary on disk and no dataset match) reports nothing and shows no banner.
